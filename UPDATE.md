# v2.5 – Sinkronisasi draft
Backup PostgreSQL, upload seluruh file ZIP ke root repository, deploy. Variabel OAuth dan SESSION_SECRET tetap. Sinkron master barang, import klasifikasi dan satuan, lalu pilih periode pendek dan modul pada dashboard. Sinkronisasi menggunakan GET saja. Empat modul dapat menulis mutasi draft; penyesuaian diblokir sampai arah terverifikasi. Setiap modul ditolak jika ada masalah mapping. Referensi stabil digunakan untuk upsert. Data manual pada periode memblokir sinkronisasi. Transaksi hilang atau pindah tanggal yang terdeteksi memerlukan rekonsiliasi manual. Tidak ada penghapusan otomatis. Jalankan ulang periode untuk pembaruan. Periode maksimum 32 hari, 100 halaman per modul; gunakan periode kecil agar request tidak timeout. Saldo awal, klasifikasi, dokumen BC, WIP dan aset perlu validasi terpisah. Laporan pemasukan/pengeluaran masih draft berdasarkan jenis IN/OUT, bukan bukti status kepabeanan. Belum diuji dengan API live atau PostgreSQL Railway.
